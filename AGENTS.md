# Правила работы с FluxGram backend

- Общаться по-русски.
- Перед изменениями проверять git status и реальные файлы задачи.
- Выполнять работу по этапам из `docs/fluxgram-appearance-backend.md`. Не начинать следующий этап до проверки и подтверждения текущего пользователем.
- После подтверждения этапа обновлять его статус в плане, указывать дату подтверждения, называть следующий этап и создавать отдельный commit со всеми относящимися к завершённой работе файлами.
- Push выполнять только по отдельному запросу пользователя.
- Не откатывать и не изменять пользовательские правки, не относящиеся к текущей задаче.
- Не выводить токены, DSN, webhook secret и другие credentials в ответы, документацию или логи.

## Python-код

- Писать читаемый Python-код и разделять логические блоки пустыми строками.
- Не уплотнять несколько действий в одну строку и не использовать сложные однострочные выражения ради краткости.
- Разворачивать условия, циклы и обработчики исключений, когда это улучшает чтение.
- Делать функции небольшими и с одной понятной ответственностью, но не создавать лишние обёртки без повторного использования.
- Использовать типы на публичных границах и в domain/application слоях.
- Отделять Pydantic API-модели от SQLAlchemy entities и domain-моделей.
- Комментарии добавлять только для неочевидных решений, а не для пересказа кода.

## Инструменты и архитектура

- Использовать Python 3.12 и `uv`; хранить `uv.lock` в Git.
- Telegram updates принимать только через webhook, включая локальную разработку с ngrok. Long polling не добавлять.
- Публичный API оставлять read-only. Административные изменения выполнять через bot application services.
- Миграции Alembic запускать отдельной командой, а не конкурентно при старте реплик.
- Для локальной базы использовать PostgreSQL 18 на Debian-based image.

## Проверки

- Для изменённой логики запускать ближайшие pytest-тесты.
- Перед завершением этапа запускать полный backend test suite, Ruff и проверку типов.
- Для изменений базы проверять миграцию вперёд и сценарий развёртывания на чистой PostgreSQL 18.
- Для webhook отдельно проверять secret token, повторную доставку update и локальный callback через ngrok.
